## Resolution

root_cause: High-confidence non-repository classification. The twelve crash popups were unrelated macroquad/miniquad `rust_out` GUI executables aborting after a non-unwinding panic in the macOS OpenGL `draw_rect` callback. The separate zero-test `_dyld_start` behavior was macOS AMFI and AppleSystemPolicy execution-policy/provenance assessment in a severely stressed long-running host session. After reboot, one later Cargo gate exposed a second host artifact: the pre-existing target/debug/deps directory blocked in APFS directory enumeration.
fix: A genuine normal full macOS reboot cleared the indefinite execution-policy stall and reset swap/load pressure. Plan verification budgets at least 120 seconds for first launch. The unreadable, ignored Cargo target tree was moved intact to a recoverable Trash path so Cargo can recreate a clean cache. No repository signing, xattr, provenance, linker, or security-policy workaround was applied.
verification: Boot time changed, swap cleared, the prior executable launched immediately, the freshly rebuilt executable became runnable after one bounded policy assessment and then listed 372 entries immediately, and Bazel reached Rust compilation in eight seconds. All review-fix commits passed complete mandatory Rust gates from fresh isolated targets. The ordinary repository target was then recreated cleanly and passed 7/7 focused tests without a stall.
